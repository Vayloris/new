# **Local Business Presence Website: AI Master Blueprint (Google AI Studio & Design Engineering Edition)**

This document is a comprehensive, deterministic prompt specification. When provided to Google AI Studio alongside the completed BUSINESS\_CONFIG JSON, the AI must generate a complete, production-ready, static-exportable Next.js (App Router) codebase. The output must feature zero missing files, zero online transactional systems, zero repetitive content spam, zero AI-generated visual clichés, strict adherence to US Federal Trade Commission (FTC) and ADA legal compliance, design-engineered lightweight animations, built-in technical Google Local SEO, and an automated inbound voice routing integration.

## **1\. Core Mandate: Pure Digital Storefront & Voice Routing (Zero Transactions)**

This site is strictly a **presence, credibility, and utility storefront** for local businesses. It communicates identity, offerings, location, hours, direct inquiries, and routes high-intent traffic to an automated voice receptionist.

* **NO online ordering systems:** No shopping carts, checkout flows, or inventory management.  
*   
* **NO third-party delivery/ordering embeds:** Do not link to or embed DoorDash, UberEats, Grubhub, or Square Online.  
*   
* **NO payment gateway code:** Zero Stripe, PayPal, or merchant processing integrations.  
*   
* **NO visible SEO or Compliance metadata:** Technical crawler metadata, schema tags, and compliance disclaimers (e.g., "FTC Compliant") must NEVER be rendered as visual UI text. All entity classification data lives strictly inside machine-readable \<head\> scripts.  
*   
* **Primary CTA \- Smart Voice Routing:** The primary sticky mobile CTA must be "Call to Book" or "Order via Voice Assistant," routing traffic directly to the inboundVoiceEndpoint to ensure all inquiries are instantly captured.  
*   
* **Serverless In-Page Inquiry Capture:** Implement an asynchronous, serverless lead form submitting via fetch() to contact.formEndpoint.  
* 

## **2\. Agency & Client Safety, Legal & Security Standards**

### **A. Americans with Disabilities Act (ADA) & Web Accessibility (WCAG 2.1 AA)**

* **Accessible Primitives:** Do not hand-roll interactive HTML elements. You MUST use open-source Radix UI / shadcn/ui primitives for all dialogs, sheets, and menus to guarantee unstyled accessibility.  
*   
* **Zero Missing Alt Text & Labels:** Every \<img\> tag must include descriptive alt text. Purely decorative elements must be flagged with aria-hidden="true". All icon-only buttons must feature automated aria-label injection.  
*   
* **Keyboard Navigation & Targets:** All interactive elements must feature visible, high-contrast focus rings (focus-visible:ring-2 focus-visible:ring-neutral-900 focus-visible:ring-offset-2). Touch targets on mobile must have a minimum size of 44x44px.  
*   
* **Color Contrast:** All body text must strictly meet or exceed WCAG AA contrast standards (minimum 4.5:1).  
* 

### **B. FTC Compliance & Authentic Social Proof**

* **Silent Review Handling:** The socialProof object in the JSON represents authentic, verified reviews pulled from Google or Yelp. Render these naturally.  
*   
* **Zero Legal Disclaimers:** NEVER print legal text, meta-commentary, or compliance warnings (e.g., "Compliant with FTC 16 CFR Part 465" or "Zero AI-generated testimonials") in the visual UI.  
*   
* **Zero AI-Generated Testimonials:** If the socialProof object is empty or null, you must completely and silently omit the Social Proof section. Do not generate placeholder reviews.  
* 

### **C. Data Privacy & Copyright Hygiene**

* **Mandatory Privacy Policy:** The footer must contain a link to a PrivacyModal.tsx component disclosing analytics and third-party form processing.  
*   
* **Defensive Asset Handling:** Only reference image paths explicitly provided in business.json. Never insert placeholder images from third-party domains.  
* 

## **3\. Advanced SEO, Telemetry & Core Web Vitals**

### **A. NAP Consistency & Head-Only Schema Integration**

* **1:1 NAP Match:** The Name, Address, and Phone number hardcoded in the codebase must match the client's verified Google Business Profile (GBP) exactly.  
*   
* **Aggressive Structured Data in** \<head\> **Only:** Dynamically inject valid schema.org/LocalBusiness, schema.org/Menu, schema.org/OfferCatalog, and schema.org/FAQPage JSON-LD into the document head.  
* 

### **B. Meta Tags & Web Vitals**

* **Single** \<h1\> **Entity Rule:** Ensure exactly one semantic \<h1\> tag exists on the page containing the business entity name and local anchor.  
*   
* **LCP & CLS Enforcement:** The hero image must carry priority={true} via next/image and must not be lazy-loaded. All below-the-fold images must use explicit aspect ratio wrappers (aspect-\[4/3\], aspect-square).  
* 

## **4\. Information Architecture & Strict Anti-Repetition Rules**

* **Zero Content Looping:** Do not repeat the same value propositions, summaries, or descriptions across multiple sections. Each section must contain unique, non-overlapping information.  
*   
* **Street Address Restriction:** The full street address belongs strictly in the Location & Hours block and the bottom footer. Never repeat it in the hero or card grids.  
*   
* **Phone Number Restriction:** Keep the phone number strictly in the header, footer, mobile bar, and the dedicated contact block.  
*   
* **Hours Isolation:** Full operating schedules belong strictly in the Location & Hours block.  
* 

## **5\. Explicit Banned Design Tropes (Anti-AI Slop Mandate)**

The model must **NEVER** use:

* ❌ Emojis AND Unicode Symbols: Absolutely zero emojis and zero Unicode symbol icons (e.g., 📞, 🕒, ✉️, ✨, 📍). You MUST use a professional SVG icon library like lucide-react for all iconography.  
*   
* ❌ Placeholder text (Lorem Ipsum). Factual, local copy only.  
*   
* ❌ Corporate filler copy (*elevate, unleash, crafting memories, seamless, reimagining, bespoke*).  
*   
* ❌ Visual metadata chips or technical audit badges anywhere in the UI.  
*   
* ❌ Chunky brutalist black borders or thick outline stacking.  
*   
* ❌ Purple, pink, or neon gradients and gradient text.  
*   
* ❌ Glassmorphism, blurred backdrop cards, or floating decorative blurs.  
* 

## **6\. Core Aesthetic & Editorial Philosophy (Design Engineering)**

1. **UI Foundation:** Use open-source shadcn/ui components exclusively.  
2.   
3. **Stark Monochrome Palette:** Light, airy background (bg-\[\#FAFAFA\] or bg-white). Use high-contrast \#000000 or \#09090b for primary text. Restrict color to a single purposeful brand accent for active buttons and links.  
4.   
5. **Subtle Structural Delimiters:** Hairline borders only (border-border or border-neutral-200/80).  
6.   
7. **Modern Typography:** Geist or Inter typeface (font-sans, tracking-tight) paired with quiet monospace accents (font-mono text-xs uppercase tracking-wider) for operational details like item prices and weekly hours.  
8.   
9. **Factual, Direct Local Copy:** Plainspoken clarity. State what the business does, where it operates, hours of service, and item pricing without embellishment.

## **7\. Technology Architecture & Emil Kowalski Motion Rules**

* **Next.js Static Engine:** Must use Next.js App Router configured with output: 'export' in next.config.mjs for instantaneous load times and zero-server deployment.  
*   
* **GitHub Open Source Libraries:** Emulate Emil Kowalski's open-source repositories for UI interaction:  
* 

  * **Sonner (**sonner**):** Implement for non-blocking form submission toasts (toast.promise).  
  *   
  * **Vaul (**vaul**):** Implement the mobile menu and action sheet using Vaul’s drawer primitive for native swipe-to-dismiss gesture physics.  
  *   
  * **Lucide React (**lucide-react**):** Implement for all icons. Do not use unicode text symbols.  
  *   
* **Emil Kowalski Micro-Interactions:**  
* 

  * Use interruptible CSS transitions (transition-all duration-150 ease-out) rather than CSS keyframes.  
  *   
  * Interactive elements must feature tactile scale feedback (active:scale-\[0.98\]).  
  *   
  * Only use native IntersectionObserver fade-ups for initial viewport entry (opacity: 0 \-\> 1, translate-y-4 \-\> 0, duration 400ms).  
  *   
* **Reduced Motion:** Respect prefers-reduced-motion: reduce for full accessibility compliance.  
*
